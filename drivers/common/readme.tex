\section{What this file is}

Every driver module in this course (GPIO, ADC, UART, \dots) starts with
\lstinline|#include "../common/common.hpp"|. You never include this file
yourself --- it comes along automatically with whichever module you use.
It provides three things:

\begin{enumerate}
  \item The MCU definition \texttt{\_\_AVR\_ATmega32A\_\_} so that
        \texttt{<avr/io.h>} exposes the correct register names.
  \item The standard AVR headers: \texttt{<avr/io.h>} (registers),
        \texttt{<avr/interrupt.h>} (ISR support, \texttt{sei()}/\texttt{cli()}) and
        \texttt{<util/delay.h>} (\texttt{\_delay\_ms()}).
  \item A set of Arduino-like constants used across all modules.
\end{enumerate}

\section{The \texttt{F\_CPU} rule}

\texttt{F\_CPU} tells the toolchain how fast your CPU clock is. Delay loops,
UART baud rates and timer calculations are all derived from it, so it must
match the \emph{real} clock of your chip (set by the fuse bits --- see the
\texttt{Makefile} targets \texttt{int-1mhz} \dots\ \texttt{ext-xtal}).

\textbf{Always define it \emph{before} the first driver include:}

\begin{lstlisting}
#define F_CPU 8000000UL   // 8 MHz -- must come first!
#include "drivers/gpio/gpio.hpp"
\end{lstlisting}

If you forget, the driver falls back to 8\,MHz and the compiler prints a
warning. A wrong \texttt{F\_CPU} does not stop compilation --- but your
delays will be wrong and your UART will print garbage. If the serial
terminal shows random characters, check \texttt{F\_CPU} and the fuses first.

\section{One source file per program}

The drivers are \emph{header-only}: all code lives in \texttt{.hpp} files and
each firmware image is built from exactly one \texttt{.cpp} file. Include
only the modules you need --- unused peripherals then cost no flash memory
and no interrupt vectors.

\section{Seven-Segment Display (\texttt{sevenseg.hpp})}

\texttt{sevenseg.hpp} is a small helper module for driving a single
\textbf{active-low, common-anode} seven-segment display that is wired
directly to \textbf{PORTB}. Include it explicitly --- it is not pulled in
automatically by other modules:

\begin{lstlisting}
#define F_CPU 8000000UL
#include "../common/sevenseg.hpp"
\end{lstlisting}

\paragraph{Wiring.} All 8 bits of \texttt{PORTB} are dedicated to the
display's segments (including the decimal point), so \texttt{PORTB} must
not be used for anything else while this module is active. The driver sets
\texttt{PORTB} directly; it does not touch \texttt{DDRB}, so you must
configure \texttt{PORTB} as \texttt{OUTPUT} yourself (e.g.\ via
\texttt{GPIO.setDirection(PORTB, ALL, OUTPUT)}) before calling it.

\paragraph{API reference.}

\begin{center}
\small
\begin{tabular}{ll}
\toprule
\textbf{Function} & \textbf{Description} \\
\midrule
\texttt{SevenSeg(digit)} & Displays \texttt{digit} (0--9) on the seven-segment \\
                         & display and returns the raw segment pattern written. \\
\bottomrule
\end{tabular}
\end{center}

\texttt{digit} is expected to be in the range \texttt{0}--\texttt{9}. Any
other value (e.g.\ from an unmasked 4-bit input of \texttt{10}--\texttt{15})
falls back to a dash-like pattern (\texttt{0b10001100}) instead of showing a
digit, which is useful for spotting out-of-range input while debugging.

\paragraph{Example: binary switches to seven-segment digit.}

\begin{lstlisting}
#define F_CPU 8000000UL
#include "../gpio/gpio.hpp"
#include "../common/sevenseg.hpp"

int main() {
  GPIO.setDirection(PORTB, ALL, OUTPUT);       // seven-segment on PORTB
  GPIO.setDirection(PORTC, ALL, INPUT_PULLUP); // DIP switches on PORTC

  while (1) {
    uint8_t value = GPIO.read(PORTC) & 0x0F; // lower 4 bits -> 0..15
    SevenSeg(value);
    _delay_ms(50);
  }
}
\end{lstlisting}
